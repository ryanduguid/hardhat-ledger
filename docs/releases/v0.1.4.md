# v0.1.4

`v0.1.4` is the protected failed-tag evidence for the cross-runtime
compatibility and safety repair. It retains the
`subcontractor-accounting-skills` plugin name and all ten skill names, but its
release run 32839062910 stopped before publication because the source-archive
test job did not install PyYAML. The annotated tag remains at
`2f29bb51957888b1f427be44a7a0866ed4f4f5e5`; no v0.1.4 release or assets exist.

## Packaging repairs

- Use one canonical nested plugin payload for Claude and Codex.
- Give the Claude plugin manifest sole ownership of its skill components.
- Point both marketplace listings to the same plugin root.
- Remove unsupported Codex manifest fields and the incorrect privacy-policy link to `SECURITY.md`.
- Keep concrete manifest versions aligned with `VERSION` while leaving marketplace listings unversioned.

## Safety repairs

- Carry current-source, client-data, secure-output, consequential-action and professional-judgement controls inside every standalone skill.
- Fail closed when no firm-approved secure output path is configured.
- Replace the Coal LSL lodgment and payment instruction with an authorised-human hand-off.
- Remove the payroll-tax repository-output fallback and the unshipped `bas-preparation` reference.
- Make the required TheWIPTally dependency consistent within the WIP skill.

## Release boundary

The tag workflow delegated to the full-commit-pinned shared release policy.
Consumer tests ran without release authority, and the privileged job would have
started from a fresh checkout before building, attesting and publishing. The
failed tag is not rerun or repaired. Its recovery is the separate v0.1.5
release process change.

## Consolidation

This release does not deprecate the repository. The gated transition to a broader Australian accounting skill pack is recorded in [the consolidation plan](../consolidation-transition.md).
